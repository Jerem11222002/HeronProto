Entity Relationships

Users & Posts 1:N USERS.UserID → POSTS.AuthorID

One user can create many posts

Users & Comments 1:N USERS.UserID → COMMENTS.AuthorID

One user can write many comments

Posts & Comments 1:N POSTS.PostID → COMMENTS.PostID

One post can have many comments

Comments & Comments (Threaded) 1:N COMMENTS.CommentID → COMMENTS.ParentCommentID

Comments can reply to other comments (nested structure)

Users & Interactions M:N USERS.UserID ↔ INTERACTIONS.UserID

Users perform multiple interactions; interactions tracked for each user

Posts & Interactions M:N POSTS.PostID ↔ INTERACTIONS.PostID

Posts receive multiple interactions; interactions reference specific posts

Users & User Preferences 1:1 USERS.UserID → USER_PREFERENCES.UserID

Each user has one preference profile

Posts & Post Similarities M:N POSTS.PostID ↔ POST_SIMILARITIES

Posts compared for similarity to other posts (recommendation algorithm)

Users & Friendships M:N USERS.UserID ↔ FRIENDSHIPS

Users have social connections with other users (followers/following)

Posts & Tags M:N POSTS.Tags[] ↔ TAGS.TagID

Posts tagged with multiple tags; tags applied to multiple posts

Tags - Content categorization
Users - User accounts & profiles
Interactions - User engagement data
Posts - User-generated content
Comments - Discussion threads
Preferences - User preference profiles
Friendships - Social connections
Similarities - Content recommendations
Implementation Notes:
  • All timestamps use UTC for consistency
  • Foreign keys ensure referential integrity
  • Arrays (denoted with []) are embedded MongoDB arrays
  • Interaction weights are normalized (0-1 scale) for scoring
  • User preferences updated incrementally based on interactions
  • Post similarities pre-calculated for performance optimization
  • All indexes created on FK fields for fast lookups
