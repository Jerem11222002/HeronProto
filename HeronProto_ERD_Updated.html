📋 Diagram Overview

The entity relationship diagrams are organized into three functional areas for clarity and documentation purposes.

Legend & Notation

PK = Primary Key (Unique identifier for each record)
FK = Foreign Key (Reference to another entity)
UK = Unique Key (Must be unique in the database)
||--o{ = One-to-Many (one record relates to multiple)
}o--|| = Many-to-One (multiple records relate to one)

🔹 Diagram 1: Core Content & Social Features

USER

Core user entity with authentication, profiles, interests, and social relationships (followers/following)

POST

User-generated content with media support, tags, likes, and comments. Can be shared by other users

COMMENT

Nested comments on posts with threading support (replies to other comments). Supports likes

🔹 Diagram 2: Events & Registrations

EVENT

Organization events with registration forms, ticketing info, and participant tracking

EVENT_REGISTRATION

Detailed registration records storing participant information, status, and event-specific details

🔹 Diagram 3: Messaging & Notifications

CONVERSATION

Direct message threads between multiple participants

MESSAGE

Individual messages with attachments, reactions, and threading (reply/forward support)

NOTIFICATION

System notifications for user activities (likes, comments, messages, follows, etc.)
